# The tank has a size — implementation plan

**Spec:** `docs/superpowers/specs/2026-09-06-tank-size-design.md` — the authority; every task
cites its decisions. Short on purpose: decisions and traps live in the spec, the code says the
rest.

**Goal:** the backend measures each board's tank with the meter and judges the float against
that volume (stuck at full: refuse and page; stuck at empty: page), announces every measurement,
and the app shows the size, the counter, the learning hint and the OVER state.

**Where:** backend in `~/projects/plant-butler/backend` on branch `tank-size` (`butler.py`,
`schema.sql`, `tests/`; run `uv run pytest -q`); app in `~/projects/plant-butler/app` on branch
`tank-size` (`app/src/main/java/garden/butler/app/{Backend,Garden,GardenScreen}.kt`, tests in
`app/src/test/java/garden/butler/app/`; run
`JAVA_HOME=/opt/homebrew/opt/openjdk@17 ./gradlew --offline -q testDebugUnitTest`).

## Backend

### Task 1 — Measure (D1–D5, D9's three read-only fields)

`schema.sql`: `tank_samples(ts, controller, refill_ts, ml, UNIQUE(controller, refill_ts))` with
an index on `(controller, ts)`; `refills.float_ok INTEGER` in the `CREATE` and in
`ADDED_COLUMNS`; `status.float_word`, the board's last word on the float, likewise, carried from
`float_ok`. `butler.py`: constants; `record_refill` snapshots `status.float_ok`;
`pumped_since(con, controller, since_ts)`; `tank_ml(con, controller)`; the sample insert in the
report transaction on a 1 → 0 `float_word` (D4, `INSERT OR IGNORE`), skipping a retired board
(D1); `/health` entries gain `tank_ml`, `tank_samples`, `pumped_ml`. Tests in a new
`tests/test_tank_size.py`: the snapshot (1, 0, NULL); the counter counts acked water sent after
the tap and nothing before it; a 1 → 0 closes one sample per tap and none with zero pumped, the
first crossing's number standing over a later one; a report without `float=` between full and
empty hides no edge; a retired board closes nothing; the median over the last five; `None`
under two samples; `/health` shape; an existing database gains the columns at startup.

### Task 2 — Judge (D6, D7, D10, D9's `over`)

`tank_state`, `float_dead`; `water_rules` skips on `"over"`; the ticker's `over:<c>` raise and
clear and the rewritten `stale:<c>` raise and clear, both skipping retired boards; `float_state`,
`REFILL_SLACK_S`, `FLOAT_AGE_CHANNEL` and the old rule removed; `/health` gains `over`. Rewrite
the D6-era tests in `tests/test_tank.py` to the new rules. New tests: over fires only above the
tolerance and only with the float at 1, refuses in the rules, pages once per floor, clears on a
tap; a top-up tapped daily never fires; `POST /command water=` still passes while over; dead
fires 180 s after a tap at empty and not for a float that went 0 → 1 → 0 after the tap; a NULL
snapshot judges nothing; a standing `stale:` from before clears when the float reads 1.

### Task 3 — Announce (D8, version)

The one-shot `tank:<c>:<refill_ts>` pages, sample and drift, marked like `dose:`; `/health`
excludes `tank:%`; retired boards skipped; `VERSION = "0.19.0"`; the module docstring and the
`schema.sql` comments no longer describe the clock rule. Tests: one page per sample, the drift
text above 25 % and the plain text below, "learning, K of 2" under two samples, the exclusion.
